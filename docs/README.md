# AI Token SaaS 方案文档索引

更新日期：2026-11-02。

平台面向企业与普通用户，按管理业务系统、LLM Gateway、Client 三个逻辑系统构建，覆盖文本流式、图片与视频异步任务。管理后台使用 React + Vite，Client 使用 Next.js，业务后端使用 TypeScript + Hono，LLM Gateway 使用 Go。

资金链路统一为：中央批次分配额度 → Go 持久额度子账预占与启动 → 可靠用量事件 → Billing 精确清算与正式记账 → 原分片幂等应用回执。Gateway 直接写自己的运行时分片，中央钱包与总账由 Billing 统一维护。

## 核心架构约束

- 生产采用单区域多可用区、多个执行 Cell；中央 business_db 与 runtime_db_<cell> 分开部署高可用 PostgreSQL。
- Go 在进程内额度模块中完成请求准入，写本分片子账、预占与执行状态；正常热路径不逐请求调用 Hono。
- 中央钱包、资金来源、全部硬预算、最终定价与正式账本由 Billing 维护；授权分配与最终消费分别记载。
- 本地 L=F+H+X+R，中央授权与本地子池按回执/回收水位对账；不根据在途差额补发资金。
- Outbox/Kafka/Inbox 与业务唯一键保证可靠清算，收到持久化回执后再释放 E-C。
- 已启动或未知任务保持冻结；授权回收先封存，权限撤销经过分片持久确认屏障。
- Redis 用于缓存与流控，ClickHouse 用于分析，对象存储用于文件；资金权威在 PostgreSQL。

100,000 并发是实施验收目标。持续 QPS、P99、厂商采购容量与故障恢复指标按工作负载和真实测试确定，验收规则见 [可靠性方案](07-reliability-and-validation.md)。
